# Utilizing LLMs in Drug Repurposing

Deterministic text-to-Cypher pipelines over biomedical knowledge graphs to accelerate indication discovery.

## Motivation

In drug research and medicine, an answer is only useful if it is correct and comes out the same every time. AI agents can now read a question, write a Cypher query, run it against a graph database and report the result. This project asks how well, and how reproducibly, current language models do this on a biomedical graph built in 2017.

## The data: Hetionet v1.0

Hetionet integrates data from public biomedical resources into one graph, originally built to predict new uses for existing drugs (Himmelstein et al., *eLife*, 2017).

- **47,031 nodes** of **11 types**, **2,250,197 relationships** of **24 types**
- Stored in Neo4j and queried with Cypher
- Public read-only server: `neo4j.het.io` (Neo4j 3.5.12 Community, no login, reached over the HTTP API)

### Things worth knowing

- The graph contains only **137 diseases** and **755 known treatments**, so coverage is limited by design.
- The data is a **2017 snapshot** and never changes, which suits reproducibility studies.
- The server runs **Neo4j 3.x**, so modern Cypher syntax (for example `EXISTS { ... }` subqueries) is not available. Agents must write older-dialect Cypher.
- Entity names are lowercase strings (`bile duct cancer`), gene identifiers are numeric, and compound names are capitalised (`Flavoxate`).

## How to run

**Requirements:** [uv](https://docs.astral.sh/uv/) and Git (uv installs Python), plus an API key for an OpenAI-compatible LLM endpoint (see `.env.example`).

```powershell
# 1. Install
git clone https://github.com/jakubradziejewski/reproducible-agents-biomedical-kg.git
cd reproducible-agents-biomedical-kg
uv sync

# 2. Configure. The public Hetionet server needs no credentials; keys are only for hosted models.
cp .env.example .env        # then edit .env. Never commit it.

# 3. Check the database connection and export its schema
uv run python src/explore_schema.py          # writes data/schema.md

# 4. Rebuild the gold questions from the hand-written Cypher
uv run python src/build_gold.py              # writes data/questions.jsonl

# 5. Self-test the evaluator
uv run python src/evaluate.py

# 6. Run agents: one question first, then the whole set with repetitions
uv run python src/run_experiments.py --models qwen3.8-27b --only q01
uv run python src/run_experiments.py --models qwen3.8-27b --reps 3
```

| Option | Meaning |
|---|---|
| `--models a,b` | Keys from `src/models.py` |
| `--only q01,q03` | Run only these questions |
| `--reps N` | Repeat each question N times (repeatability) |
| `--max-steps N` | Max tool calls per run (default 6) |
